## 1. 매뉴얼에서 확인한 규칙 (확정 사항)

### 1.1 진행 방식
| 항목 | 내용 | 매뉴얼 |
|---|---|---|
| 통신 | 클라이언트가 `127.0.0.1:8747`에 TCP 접속 → `INIT 닉네임` 전송 → 이후 **내 차례마다** 상태 문자열을 받고 커맨드 1개를 보냄 | p.11, p.20 |
| 팀 구성 | 2팀, 팀당 1~3명. 접속 순서대로 A/B 자동 배정. 양 팀 동수일 때만 시작 | p.19~21 |
| 선/후공 | 동점 판정 3순위가 "후공으로 플레이한 팀 승리" → 선공/후공이 존재 (A가 선공으로 추정) | p.22 |
| 턴 | 탱크별로 차례가 돌아가며, 모든 탱크가 100턴에 도달하면 종료 | p.22 |
| 기본 탄약 | 팀전 스크린샷 기준 일반 포탄 999, 메가 포탄 0 | p.22 |

### 1.2 즉시 종료 조건 (우선순위 순)
1. 차례가 된 탱크의 **시간 초과 / 런타임 오류** → 해당 팀 패배 ⚠️ 가장 치명적
2. **상대 포탑 파괴** → 파괴한 팀 승리
3. 한 팀의 탱크가 상대 공격 또는 **페널티**로 **2대 파괴**(또는 전멸) → 해당 팀 패배
4. 모든 탱크가 100턴 도달 → (a) 탱크+포탑 **피해가 적은 팀** 승리 → (b) **탱크와 적 포탑 간 거리 합**이 작은 팀 → (c) **후공 팀**

### 1.3 입력 데이터
```
[세로H] [가로W] [아군 수] [적군 수] [암호문 수]
H개 행: 맵 (공백 구분)
아군: M [체력] [방향] [일반탄] [메가탄] / M1~M3 [체력] / H [체력]
적군: E1~E3 [체력] / X [체력]
암호문: 보급시설과 상하좌우 인접 시에만 1줄
```
| 기호 | 의미 | 이동 | 포탄 |
|---|---|---|---|
| G | 일반 지형 | 가능 | 통과 |
| S | 모래 | 가능 (진입 시 체력 -10) | 통과 |
| W | 물 | 불가 | **통과** |
| T | 나무 | 불가 | 막힘 (포탄으로 파괴 가능) |
| R | 바위 | 불가 | 막힘 (파괴 불가) |
| F | 보급시설 | 불가 | 막힘 (파괴 불가) |
| M / M1~M3 / H | 나 / 아군 탱크 / 아군 포탑 | 불가 | 피격 |
| E1~E3 / X | 적 탱크 / 적 포탑 | 불가 | 피격 |

### 1.4 커맨드 (최대 3토큰: `[방향] 행동 [옵션]`)
| 커맨드 | 효과 |
|---|---|
| `U/D/L/R A` | 해당 방향으로 회전 후 1칸 전진 (회전+이동이 1턴) |
| `U/D/L/R F` | 회전 후 일반 포탄 발사 (사거리 3, 피해 30) |
| `U/D/L/R F M` | 회전 후 메가 포탄 발사 (사거리 3, 피해 70) — 보유 0개면 **턴만 소모** |
| `G 평문` | 보급시설 인접 시 카이사르 암호 해독 → 성공 시 메가 포탄 +1, 실패 시 턴만 소모 |
| `S` | 제자리 대기 |

### 1.5 보급시설 / 암호
- 보급시설(F) 상하좌우 인접 칸에서만 암호문을 받음 (바라보는 방향 무관, 대각선 불가)
- 카이사르 암호, **한 게임 동안 이동값 고정**, 암호문은 매 턴 바뀜
- 보급시설은 사라지지 않음 → 같은 자리에서 반복 획득 가능 (단, 1회 = 1턴)

## 3. 불확실 사항과 대응 원칙

| 불확실 사항 | 시뮬레이터 가정 | 봇의 대응 (가정에 의존하지 않도록) |
|---|---|---|
| 턴 순서 (A1→B1→A2… / A1→A2→A3→B1…) | 두 방식 모두 시뮬레이션 | 매 턴 실제 상태를 다시 읽고 판단 (순서 무관) |
| 팀전 포탑 체력 | 10 / 100 두 경우 시뮬레이션 | 입력 데이터의 실제 체력 사용 |
| 포탑 주변 색칠 구역 기호 | 일반 지형(G)으로 가정 | **모르는 기호는 이동 불가·포탄 통과**로 처리, 로그에 기록 |
| 페널티 조건 | 무효 커맨드 횟수만 집계 | **무효 커맨드 0회** 보장(이동/발사/해독 전 검증), 아군 오사격 금지, 설명 안 되는 체력 감소는 로그에 `UNEXPLAINED` 로 기록 |
| 나무 내구도 | 1발에 파괴 | 쏜 뒤 남아 있으면 다시 사격 (매 턴 재계획), 로그 기록 |
| 이동 실패 칸 | - | 이동 명령 후 위치가 안 바뀌면 해당 칸을 **진입불가로 학습** |
| 턴당 시간 제한 | 3초 | 턴당 연산 수 ms 수준 (16x16 다익스트라 몇 번) |

**안전 원칙 (모든 설계 공통)**
1. 소켓 통신부(`init/submit/receive/close`)는 한 글자도 수정하지 않는다.
2. 판단 로직 전체를 `try/catch(Throwable)` 로 감싸 **어떤 예외도 연결을 끊지 않는다** (실패 시 `S`).
3. 무효 커맨드 금지: 막힌 칸 이동, 탄 없는 발사, 아군/아군포탑 사선 발사, 보급시설 미인접 해독을 생성 단계에서 배제.

## 4. 핵심 전술 분석

### 4.1 "선빵"의 법칙
한 턴에 **이동 또는 사격** 중 하나만 가능하고 사선(LOS)은 대칭(같은 직선, 같은 사거리 3)이다.
- 내가 적의 사선 **안으로 걸어 들어가면** → 적이 먼저 쏜다.
- 적이 내 사선 안으로 들어오면 → 내가 먼저 쏜다.

체력 100, 일반탄 30 → 4발 필요. 먼저 쏘는 쪽이 `내가 필요한 발 수 ≤ 상대가 필요한 발 수` 이면 이긴다.
→ **"사선에 먼저 들어가지 말고, 들어오는 적을 먼저 쏜다"** 가 기본.

### 4.2 메가 포탄이 결투를 뒤집는다
메가(70)+일반(30)=100 → **2발 킬**. 메가가 있으면 적 사선에 먼저 들어가 한 대 맞아도 이긴다.
(적이 먼저 쏨 → 나 70 → 적 30 → 나 70(적 사망), 내 체력 40 생존)
→ 안전할 때 보급시설에서 메가를 확보하는 것은 턴 대비 가치가 크다.

### 4.3 포탑 완전 봉쇄
포탄은 직선으로만 날아간다. 포탑과 **인접한 칸**에 아군 탱크가 서 있으면 그 방향의 모든 사격이 막힌다.
코너 포탑(H=(15,0))은 열린 방향이 위·오른쪽 2개뿐 → **탱크 2대로 포탑을 무적화**할 수 있다.
그 탱크들은 접근하는 적에게 항상 선빵을 친다.

### 4.4 승리 경로
1. 적 포탑 파괴 (가장 확실)
2. 적 탱크 2대 격파 (선빵 + 메가로 달성 가능)
3. 100턴 판정: 피해 최소화 → 거리 합 → 후공

## 5. 설계안

공통 엔진: 파싱 → 보드 구성 → 사선/위협 계산 → 역할별 목표 지점 다익스트라 거리맵 →
후보 행동(대기, 4방향 이동, 4방향 일반/메가 사격, 해독)을 1수 앞까지 시뮬레이션해 점수화 → 최고점 행동.

### 설계안 A — Blitz (공격 집중형)
- 3대 모두 **적 포탑 사격 지점**(포탑과 같은 행/열, 거리 ≤3, 바위/보급시설 없음)으로 최단 경로 돌진
- 경로상 나무는 쏴서 제거, 사선에 들어온 적은 사격, 포탑 사선 확보 시 즉시 사격(메가 우선)
- 위험 회피 가중치 낮음, 메가 파밍 없음
- 가설: 포탑 체력이 낮거나 상대가 수비를 안 하면 가장 빠르게 이긴다

### 설계안 B — Fortress (수비 요새형)
- 2대는 **포탑 봉쇄 칸**(포탑 인접, 열린 방향마다 1칸)에 고정 배치 → 포탑 무적화 + 선빵 요격
- 1대는 보급시설에서 메가 4개까지 파밍 후, 신중하게(위험 가중치 높음) 적 포탑 접근
- 가설: 돌격형 상대를 선빵으로 2대 격파하거나 피해 판정으로 이긴다

### 설계안 C — Adaptive (적응형 하이브리드)
- 역할을 매 턴 **결정적(deterministic) 규칙**으로 재배정 → 아군 봇끼리 통신 없이 같은 결론
  - 탱크 수 3대: 수비 2 + 공격 1, 2대: 수비 1 + 공격 1 (봉쇄 칸이 적으면 그만큼)
  - 수비 역할은 **적이 포탑에 도달하기까지 여유가 있으면** 보급시설에서 메가를 파밍하다가 위협이 오면 복귀
  - 공격 역할은 초반에 가까운 보급시설에서 메가 2개 확보 후 공격
- 결투 계산: 사격 시 "남은 발 수 비교"로 이기는 결투만 계속, 지는 결투는 사선 이탈
- 사냥: 메가 우위로 적이 먼저 쏴도 이기는 경우에만 적 사선 진입 허용
- 후반(85턴~): 피해량 비교 → 앞서면 안전 운영, 동점이면 거리 합을 줄이도록 전진, 뒤지면 공격적으로

### 설계안별 점수 함수 가중치 개요
| 항목 | A | B | C |
|---|---|---|---|
| 목표 접근(1칸당) | 높음 | 보통 | 보통 |
| 적 사선 노출 패널티 | 낮음 | 높음 | 보통 |
| 아군 포탑 노출 패널티 | 낮음 | 높음 | 높음 |
| 수비 역할 | 0대 | 2대 고정 | 위협 기반 2대 (여유 시 파밍) |
| 메가 파밍 목표 | 0 | 4 (공격수) | 공격 2 / 수비 3 |
| 결투/사냥 로직 | 없음 | 있음 | 있음 |

## 5-1. 운영 안내(과목평가/팀전 안내 PDF)에서 추가 확인한 규칙

| 항목 | 내용 | 대응 |
|---|---|---|
| 팀전 응답 제한 | **6초 이상 응답 없으면 게임 자동 종료** | 턴당 연산 수 ms (시뮬레이션 최대 ~200ms, JIT 워밍업 포함) |
| 페널티 | **배틀 진행을 방해하면 옐로카드 1장, 3장 누적 시 해당 탱크 맵에서 제외** | 무효 커맨드 0회, 즉시 응답, 연속 대기(S) 3회째는 제자리 무해 사격으로 대체(`ANTI_IDLE_TURNS`) |
| 포탄 | 사거리 내 **가장 가까운 장애물 1개만 파괴**, 풀/물은 장애물 아님 | 시뮬레이터/봇 모두 동일 규칙 |
| 제출 | `Player1_지역반_이름.java` 형식, **코드 순서 Player1 > Player2 > Player3 지정** | 슬롯(시작 위치)별 역할 코드를 고정 배치 가능 |
| 닉네임 | `지역반_이름` | 각 코드의 NICKNAME 수정 필요 |

**옐로카드 원인 추정**: 매뉴얼 스크린샷에서 노란 카드를 받은 P2/P5는 대칭 위치이고, 같은 게임에서 P6은 11턴에 연결이 끊겼다.
원본 코드의 BFS는 인접한 나무에서 무한 증식하므로(시뮬레이터에서 실제로 시간 초과 재현) **응답 지연 = 진행 방해**일 가능성이 가장 높다.
다만 "제자리에 멈춰있는 경우"라는 질문에 대한 답이었으므로 **장시간 연속 대기**도 위험 요소로 보고 대응했다.

## 5-2. 팀 전략 설계 (3개 코드 = 3개 역할)

3:3 팀전이므로 3개 코드가 각자 다른 역할을 맡는 조합을 설계하고 시뮬레이션으로 최적 조합을 고른다.
아군이 어떤 코드인지(라벨) 몰라도 동작하도록 **협동은 아군 위치 기반**으로 계산한다.

| 역할 | 목표 | 협동 메커니즘 |
|---|---|---|
| GUARD1 / GUARD2 | 포탑의 1번/2번 열린 방향 봉쇄 칸 점유. 적 도착 전 여유가 있으면 가까운 보급시설에서 메가 3개 파밍 후 복귀 | 포탑 무적화 + 접근하는 적에게 선빵 |
| STRIKER | 메가 2개 확보 후 적 포탑 사격 지점으로 진격 | 수비조가 버티는 동안 포탑 파괴로 승리 |
| BAIT (유인) | 지금은 적 사선 밖이지만, 적이 나를 쏘려고 들어올 칸이 **아군 사선에 덮인** 위치에 선다 | 적이 미끼를 물면 엄호조가 먼저 쏜다 (유인-매복) |
| OVERWATCH (엄호/후미) | 아군 탱크·포탑을 쏠 수 있는 "위협 칸" 중 적이 곧 도달 가능한 칸을 최대한 많이 사선으로 덮는 위치 | 크로스파이어: 아군을 공격하러 들어온 적을 후미에서 선빵 |
| HUNTER | 메가 2개 확보 후 가깝고 약한 적 탱크 추적, 이기는 결투만 건다 | 2대 격파 승리 노림 |

### 7.1 1차: 동일 코드 3대 설계안 비교 (`results/league_v3.csv`, `league_v5.csv`, 800게임)

시뮬레이션으로 찾아 고친 문제:
1. 모래를 밟아 100턴 피해 판정에서 짐 → 경로 비용 상향, 진척 점수에서 모래 이중계산 제거, 후반 동점/우세 시 모래 금지
2. 체력 낮은 수비 탱크가 자리를 비워 포탑 파괴 → "포탑 파괴까지 남은 라운드" 기반 패배급 패널티
3. 할 일 없을 때 무한 해독 → 메가 가치가 있을 때만 해독
4. 공격 정체 시 지원 복귀 / 수비 파밍 거리 확대 → 절제 실험(`tune_v1.csv`)에서 오히려 -4%p → 끔

### 7.2 2차: 3:3 역할 조합 (`results/team_v1~v5.csv`, 총 7,080게임)
| 리그 | 1위 | 2위 | 비고 |
|---|---|---|---|
| team_v1 (12조합) | AUTO×3 74.4% = GUARD+HUNTER+STRIKER 74.4% | GUARD×2+STRIKER 66.9% | 유인/엄호(BAIT, OVERWATCH) 조합은 32~50%로 부진 |
| team_v2/v3 (새 맵) | GUARD+HUNTERD+STRIKER 75.3% | GUARD+HUNTER+STRIKER 74.7% | AUTO×3은 맵에 따라 D 상대 3%까지 추락 |
| team_v4 (포탑 구역 규칙 적용) | **SENTRY+BACKDOOR1+HUNTERD 68.7%** | AUTO×3 59.7% | 사용자 제안 SENTRY+BACKDOOR×2 = 54.7% |
| team_v5 (확인) | **SENTRY+BACKDOOR1+HUNTERD 71.7%** | GUARD1+BACKDOOR1+HUNTERD 66.0% | 모든 상대 유형에 50% 이상 |

**유인/엄호가 부진한 이유**: 미끼 탱크가 노리는 "적이 들어올 칸"은 적이 한 칸만 움직여도 바뀌고, 신중한 적은 크로스파이어 칸에 들어오지 않아
미끼만 피해를 본다. 반면 사냥조는 "메가 우위로 먼저 맞아도 이기는 결투"만 걸어 확실한 이득을 낸다.

### 7.3 실전 피드백 반영 (사용자 보고: 아군 포탑으로 가다가 페널티 받고 제외됨)
- 원인 추정: 포탑 주변 3x3 색칠 구역 진입이 '진행 방해'로 판정 → **양쪽 포탑 구역(체비셰프 거리 ≤ 2) 진입 금지** (`Cfg.TURRET_ZONE`)
  - 구역 안에 있으면 포탑에서 멀어지는 방향만 허용, 시뮬레이터에도 "구역 진입 = 옐로카드, 3장 = 제거" 규칙 추가 → 우리 봇 옐로카드 0회
- **최대 사거리 우선**: 사격 지점 중 표적과 거리 3인 칸을 선호 (가까울수록 비용 +0.4/칸) — 구역 금지와 맞물려 포탑은 항상 거리 3에서 포격
- **보급 적극 활용**: 백도어 메가 3개, 수비 2개(빠른 보급 후 복귀), 사냥 2개 목표
- **백도어의 유기적 교전**: 반경 5 안의 적 탱크와 "먼저 맞아도 이기는" 결투가 성립하면 포탑 대신 그 탱크를 공격, 사선 안의 적은 항상 즉시 사격 후보

## 8. 최종 팀 구성 (제출용)

| 순서 | 역할 | 동작 |
|---|---|---|
| **Player1** | **SENTRY** (좁은 각도 수비) | 포탑 구역 밖에서 포탑 사격 지점들을 한꺼번에 사선에 두는 칸을 지킴 (연습맵 기준 (12,3)이 (12,0)·(15,3)을 동시에 감시). 적이 오기 전 여유가 있으면 가까운 보급시설에서 메가 2개만 빠르게 확보하고 복귀 |
| **Player2** | **BACKDOOR1** (침투 타격) | 메가 3개 확보 → 적 사선 칸에 비용을 매긴 침투 경로로 적 포탑의 한쪽 방향 거리-3 사격 지점에 도착해 포격 (메가 우선). 가까운 적과 유리한 결투면 그 탱크부터 |
| **Player3** | **HUNTERD** (방어형 사냥) | 메가 2개 확보 → 아군 포탑에 가까운 적을 우선 추적, 이기는 결투만 걸어 2대 격파 승리 또는 피해량 판정 우위 확보 |

연습맵에서 Player1이 포탑에 가장 가까운 위치에서 시작하므로 수비 역할을 Player1에 배치했다. 역할 로직 자체는 시작 위치에 의존하지 않는다.

## 9. 남은 불확실성과 실전 확인 포인트
- 포탑 구역이 정말 페널티 원인인지 → 로그의 `MOVE_FAIL`, 옐로카드 시점과 `CHOICE` 대조. 아니면 `TURRET_ZONE = 0`
- 연속 대기 페널티 여부 → 무해 사격 주기 `ANTI_IDLE_TURNS` 조정
- 팀전 포탑 체력, 턴 순서, 거리 판정 방식(맨해튼 가정)
- 시뮬레이션 상대는 내가 만든 봇들이므로 실제 학생 봇과는 분포가 다를 수 있음
